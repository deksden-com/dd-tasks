# Закрытие DEF по плану

Этот промпт не запускается пользователем напрямую. Его использует оркестратор после `def/plan.md`, когда есть план закрытия конкретного `DEF-*`.

Оркестратор передаёт тебе только операционные сведения:

- какой `DEF-*` закрываем;
- какой DEF-plan читать;
- какие файлы можно менять;
- какие файлы менять нельзя;
- какие проверки запускать;
- куда записать отчёт.

Общие правила ты читаешь сам из этого файла и связанных правил MBB.

Следуй `target_language`, переданному оркестратором или определённому по `common/style.md`: пользовательские summaries/final report content должны быть на целевом языке; внутренний DEF-fix report может быть английским, если оркестратор затем синтезирует пользовательский слой.

## Обязательный контекст

Прочитай:

- `.memory-bank/dd-flow/common/style.md`
- `.memory-bank/dd-flow/common/memorybank.md`
- `.memory-bank/dd-flow/common/memorybank-git.md`
- `.memory-bank/dd-flow/common/closure.md`
- `.memory-bank/mbb/named-deferrals-guide.md`
- исходный `DEF-*`;
- план из `def/plan.md`;
- документы и код, указанные в плане.

## Задача

Выполни план закрытия `DEF-*`, собери доказательства и обнови сам `DEF-*`.

Режим Git: `memorybank_fix`, если закрытие DEF меняет Банк памяти или код. Если оркестратор уже выполнил preflight и передал состояние, используй его; иначе проверь сам.

## Правила работы

- Не расширяй scope сверх плана без причины.
- Если план оказался неверным, остановись и обнови отчёт: что не сходится и какой следующий gate.
- Если нужен пользователь, не имитируй решение за него.
- Если работа больше заявленного DEF, предложи follow-up протокол.
- Не закрывай `DEF-*`, если проверка не выполнена или доказательства не подтверждают результат.
- Если `DEF-*` закрыт частично, оставь его открытым и уточни next gate.

## Проверки

Минимум:

- проверь файлы, которые изменил;
- запусти команды из плана, если они применимы;
- проверь ссылки и индексы, если менялась документация;
- проверь сценарии или evidence, если `DEF-*` связан с приемкой;
- выполни `git diff --check` по изменённым файлам, если проект не имеет более точной проверки.

Если проверка невозможна, не называй `DEF-*` закрытым. Зафиксируй причину, владельца, что блокируется и next gate.

## Обновление DEF

После работы обнови `DEF-*`:

- `status: closed`, если закрыт полностью;
- `status: open`, если не закрыт;
- `status: blocked_by_user`, если нужен пользователь;
- `status: followup_required`, если нужен отдельный follow-up протокол;
- `status: superseded`, если закрыт другим DEF или объединён.

Добавь раздел:

```markdown
## Closure Attempt

- date:
- executor:
- changed_files:
- checks:
- evidence:
- result:
- remaining_gap:
- next_gate:
```

## Формат отчёта

Запиши отчёт в путь, который передал оркестратор:

```markdown
# DEF fix report: <DEF-ID>

## Выполнено

- ...

## Изменённые файлы

- ...

## Проверки

- команда/сценарий:
- результат:
- что доказывает:

## Итог по DEF

- status:
- closure state:
- remaining gap:
- next gate:

## Нужен пользователь

- required: true | false
- question:
- options:
- recommendation:
```
