# Prime Scout: Patterns

## Цель

Найти аналогичные места в проекте, чтобы не изобретать новый стиль и не задавать пользователю вопросы, которые можно снять существующим паттерном.

## Прочитай и проверь

- похожие экраны, компоненты, команды, API-операции, SDK-методы, сценарии;
- соседние файлы в той же папке;
- спецификации и UI-документы похожих возможностей;
- тесты или сценарии похожего поведения;
- принятые ADR, если похожая развилка уже решалась.

## Ответь

- Есть ли уже аналогичная реализация?
- Какой паттерн стоит повторить?
- Где пользовательская хотелка может быть неявно расширена по аналогии?
- Какие отличия нужно явно проговорить?
- Какие вопросы к пользователю остаются, если аналогия не даёт ответа?

## Рекомендации для flow profile

Подскажи:

- `route.planning`: можно ли ограничиться `short`;
- `documentation.impact` и `documentation.targets`: нужно ли обновить документ, чтобы закрепить повторяемый паттерн;
- `verification.plan`: какие проверки использует аналогичная часть проекта;
- `verification.plan.scenarios`: есть ли сценарий, который можно переиспользовать или расширить.
