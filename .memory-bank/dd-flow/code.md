# Code and readiness

## Active vNext

For active vNext, use only the exact CODE continuation returned for the selected
RUN and its frozen engine binding. Execute the supplied stage-start command as
the first practical command; its complete packet owns Work dispatch, workspace,
bootstrap, checks, repair and result admission. `vnext/code.md` is methodology
included by that packet, not an alternative manual dispatcher.

Do not infer a transition from legacy `ready_for_merge`. CODE-REVIEW is entered
or skipped only through the accepted frozen policy and the actual CLI directive.
Do not call legacy readiness or merge-job prompts to bypass that directive.
Missing binding, packet or predecessor evidence is a blocker, not permission to
register a new RUN, reconstruct runtime state or switch to another home.

## Retained legacy route

The instructions below apply only to an explicitly selected compatible legacy
RUN. They do not define active vNext result schemas or stage transitions. Use
the selected engine's schema, not a refreshed canon schema from another generation.

Read `common/runtime-contract.md`, `common/flow-runs.md`,
`common/runtime-cli.md`, `common/lifecycle-guards.md`, `common/style.md`, the
selected protocol summary/specification and the accepted
`.memory-bank/protocol/<PRT-ID>/plan.json` handoff. Validate the plan revision
and SHA before implementation; runtime progress is not a second plan.

## Guards

Before mutation, confirm:

1. the stable project root and feature workspace are the selected route;
2. the protocol is non-terminal and its specification and plan handoff exist;
3. active DEFs are classified;
4. the workspace bootstrap receipt is passing or explicitly
   `bootstrap_not_required`;
5. the CLI compatibility and operation preflight pass.

If any predecessor is missing, stop with `blocked: code_flow_requires_plan_ready`.
Do not repair runtime state manually and do not merge from this entrypoint.

## Route

- No implementation artifacts yet: run `mb-sdlc/code/implement.md`.
- Implementation exists but readiness was interrupted: run
  `mb-sdlc/code/readiness.md`.
- Readiness is `ready_for_merge`: hand off to `merge.md` or the project merge
  worker. Do not claim the merge lane here.

The stage prompt generated by `stage start` is the only required prompt input.
Use its `@stage` alias for writes. `@stage/try-NNN` is archive history and is
read-only.
