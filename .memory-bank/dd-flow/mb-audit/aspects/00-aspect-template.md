# Шаблон аспекта аудита

Этот файл задаёт формат аспектов для `mb-audit`. Аспект - это не самостоятельная фаза разработки, а проверочная плоскость, которую оркестратор может превратить в задачу для субагента.

## Поля аспекта

Каждый аспект должен содержать:

- цель проверки;
- когда запускать;
- нормативную базу MBB;
- проектные документы для чтения;
- что проверять;
- признаки проблемы;
- что не считать проблемой;
- какие `DEF-*` создавать;
- формат отчёта.

## Принцип нормативной базы

Аспект не должен проверять "как кажется правильным". Он обязан опираться на:

- общие правила MBB;
- профильные MBB-документы;
- проектный Банк памяти как локальный источник истины;
- код и конфигурацию, если аспект проверяет актуальность документации относительно реализации.

Если MBB и проектные правила расходятся, аспект должен зафиксировать противоречие, а не выбирать молча.
